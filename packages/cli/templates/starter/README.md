# {{name}}

A Takebase project: a global Worker for identity and tenants, one tenant Worker per
tenant with its own D1 database, and a small SvelteKit app. A signed-in member creates
notes in a tenant, and every open browser refetches them when a realtime signal arrives.

Generated by `takebase create` or `takebase init`.

## Run it locally

You need Node.js 24, pnpm, the Firebase CLI (`firebase-tools`) and Java for its emulators.

The `@takebase/*` packages are not on a registry yet, so `pnpm install` only works with
`overrides` in `pnpm-workspace.yaml` pointing at locally packed tarballs.

```sh
pnpm install
pnpm dev         # http://localhost:5173
pnpm dev:stop    # frees the ports if anything keeps one after Ctrl-C
```

Sign in as `demo@example.test` with the password `local-only-password`. Everything runs on
emulators and local D1; no Firebase or Cloudflare account is used.

## Where things are

| Path | What it is |
|---|---|
| `workers/tenant/src/schema` | Your tables. Import builders from `@takebase/core/schema` |
| `workers/tenant/src/collections` | Your collections: rules and validation. Every operation without a rule is denied |
| `workers/global` | Identity, tenants and memberships |
| `app` | The SvelteKit app, which uses `@takebase/sdk` |
| `migrations` | D1 migrations. Applied ones are never rewritten |
| `takebase.jsonc` | Environments and tenants |

## Common commands

```sh
pnpm exec takebase collection create claims --field title:text --worker workers/tenant
pnpm exec takebase migrate generate --name create_claims --worker workers/tenant
pnpm exec takebase --help
```

`pnpm dev` applies pending migrations to each tenant. Keep secrets out of the repository:
`ops/` and `.dev.vars` are git-ignored, and this starter ships no credentials.
